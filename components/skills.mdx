Skills are specialized instruction sets that teach your AI agent domain-specific patterns, conventions, and workflows. Each skill is a markdown file that gets loaded when the agent detects a matching context.

## What it does

Skills provide:
- **Context-triggered loading**: Agent detects when a skill applies
- **Pattern libraries**: Proven patterns for common tasks
- **Convention enforcement**: Consistent code style and structure
- **Workflow guidance**: Step-by-step execution templates
- **Real examples**: Copy-paste starting points

## Installation

Skills are installed as:
- Individual `SKILL.md` files written to your agent's skills directory
- Organized in subdirectories by skill name
- Auto-detected by agents that support the skills protocol

### What gets configured

<Info>
Skills directory location depends on which agent you're configuring.
</Info>

- Claude Code: `~/.claude/skills/{skill-name}/SKILL.md`
- OpenCode: `~/.config/opencode/skills/{skill-name}/SKILL.md`
- Gemini CLI: `~/.gemini/agents/{skill-name}.md`
- Cursor: `~/.cursor/skills/{skill-name}/SKILL.md`
- VS Code Copilot: `~/.copilot/skills/{skill-name}/SKILL.md`

## Skill file structure

Every skill follows this format:

```markdown
---
name: skill-id
description: One-line summary. Trigger conditions.
license: MIT
metadata:
  author: gentleman-programming
  version: "1.0"
---

## When to Use

Use this skill when:
- [Specific context or trigger]
- [File pattern or task type]

## Critical Patterns

### Pattern 1: Name

[Description]

```language
[Code example]
```

### Pattern 2: Name

[Description]

## Anti-Patterns

- [What to avoid and why]

## Examples

### Example 1

[Real-world usage]
```

## How agents use skills

### Auto-detection

Agents check for trigger conditions:
- File extensions (`.go`, `.ts`, `.py`)
- User intent keywords ("test", "refactor", "sdd init")
- Framework imports (React, Angular, Bubbletea)
- Task context (writing tests, creating components)

### Loading sequence

1. Agent detects matching context
2. Loads skill file from skills directory
3. Follows patterns and conventions in the skill
4. Applies patterns to current task

### Multiple skills

Multiple skills can apply simultaneously:

```typescript
// Context: Writing React tests
// Skills loaded:
// - react-testing
// - vitest-patterns
// - skill-creator (if creating new test helpers)
```

## Custom skills

You can create custom skills for your team:

<Steps>
<Step title="Use the skill-creator skill">
Ask your agent to create a new skill:

```bash
"Create a skill for our React component architecture pattern"
```
</Step>

<Step title="Define trigger conditions">
Specify when the skill should load:

```yaml
---
name: my-react-patterns
description: >
  Custom React patterns for our team.
  Trigger: Creating React components in src/components/
---
```
</Step>

<Step title="Document patterns">
Add your team's patterns with examples:

```markdown
## Critical Patterns

### Pattern 1: Component structure

All components follow this structure:
- props.ts - TypeScript interfaces
- Component.tsx - Main component
- Component.test.tsx - Tests
- index.ts - Public exports
```
</Step>

<Step title="Save to skills directory">
Write the skill file:

```bash
~/.config/opencode/skills/my-react-patterns/SKILL.md
```
</Step>
</Steps>
