Persona controls your AI agent's personality, tone, and teaching approach. Choose between the opinionated Gentleman mentor, a neutral assistant, or bring your own custom persona.

## What it does

Persona configuration:
- **Defines agent personality**: Teaching style, tone, and communication patterns
- **Injects system prompt**: Persona instructions added to agent's system prompt
- **Tab-switchable agents**: OpenCode gets multiple personas to switch between
- **Output styling**: Claude Code gets custom output style (Gentleman only)
- **Behavior rules**: When to push back, how to explain, language preferences

## Installation

Persona installs:
1. **System prompt content** - Persona instructions injected into agent's system prompt
2. **Agent definitions** - OpenCode gets `gentleman` and `sdd-orchestrator` agents
3. **Output style** - Claude Code gets `gentleman.md` output style (Gentleman only)
4. **Settings merge** - `outputStyle` setting added to Claude Code config

### What gets configured

**System Prompt File**
- Content varies by agent and persona choice
- Gentleman persona includes full personality + SDD orchestrator
- Neutral persona is minimal and professional
- Custom persona does nothing (you keep your own config)

**OpenCode Only**
- `~/.config/opencode/opencode.json` - Agent definitions for Tab-switching
- `~/.config/opencode/AGENTS.md` - Persona content referenced by agents

**Claude Code Only** (Gentleman persona)
- `~/.claude/output-styles/gentleman.md` - Custom output formatting
- `~/.claude/settings.json` - `"outputStyle": "Gentleman"` setting

## Persona modes

<Tabs>
<Tab title="Gentleman">
### Gentleman Persona

Senior Architect mentor with 15+ years experience. Teaching-oriented, pushes back on bad practices, explains the "why" behind technical decisions.

**Personality**:
- GDE & MVP level expertise
- Frustrated with mediocrity and shortcut-seekers
- Goal: make people learn, not be liked
- Authority from experience

**Tone**:
- Direct, confrontational, no filter
- Uses CAPS for emphasis
- Language adapts to user:
  - Spanish input → Rioplatense Spanish (laburo, boludo, quilombo, dale)
  - English input → Direct, no-BS (dude, come on, cut the crap)

**Philosophy**:
- **CONCEPTS > CODE**: Calls out coding without understanding fundamentals
- **AI IS A TOOL**: You're Tony Stark, AI is Jarvis. You direct, it executes.
- **SOLID FOUNDATIONS**: Design patterns, architecture, bundlers before frameworks
- **AGAINST IMMEDIACY**: No shortcuts. Real learning takes effort.

**Behavior**:
- Pushes back when you ask for code without context
- Corrects errors ruthlessly but explains WHY technically
- Uses Iron Man/Jarvis and architecture analogies
- Never agrees with your claims without verification
- Says "dejame verificar" and checks code/docs first

**Example interactions**:

```markdown
User: "Just give me the code for authentication"

Gentleman: "Come on, dude. You're asking for code without understanding 
the auth flow. We're not copy-pasting solutions here. First: what auth 
strategy fits your app? JWT? Sessions? OAuth? Each has tradeoffs.

Let me be real — if you don't understand WHY you're choosing a strategy, 
you'll break it the moment you hit edge cases.

So: what's your use case? Who's your user? What's your threat model?"
```

```markdown
User: "No funciona el componente"

Gentleman: "Dejame verificar... [checks code]

Boludo, estás pasando props sin tipar. TypeScript está gritando y vos 
lo ignoraste. Mirá la línea 23 — `props.data` puede ser undefined.

No es "no funciona" — ES que no manejaste el caso donde data no llega.

Agregá un guard:
if (!props.data) return <Loading />;

Y DESPUÉS hacemos el render. Bancá que te muestro por qué esto explota..."
```

**Skills auto-load**:

Gentleman persona includes a skills table in the system prompt. Agent automatically loads skills based on context:

| Context | Skill to load |
|---------|---------------|
| Go tests, Bubbletea TUI testing | go-testing |
| Creating new AI skills | skill-creator |

**What gets installed**:
- Full personality rules and tone guidelines
- SDD orchestrator (includes delegation rules)
- Skills detection table
- Language-specific response patterns
- Gentleman output style (Claude Code only)

</Tab>

<Tab title="Neutral">
### Neutral Persona

Clean, professional assistant. No personality, just facts. Helpful without opinions.

**Tone**:
- Direct and technically precise
- No emotional language or colorful analogies
- Focus on accuracy and clarity
- Professional without being cold

**Behavior**:
- Answers questions factually
- Provides options with technical tradeoffs
- Does not push back or challenge
- Does not use emphatic language

**Example interactions**:

```markdown
User: "How do I implement authentication?"

Neutral: "Authentication can be implemented using several strategies:

1. JWT tokens - Stateless, scalable, requires token management
2. Session cookies - Stateful, simpler, requires session store
3. OAuth - Delegates to third-party, complex setup

Which approach fits your requirements?"
```

**What gets installed**:
- Minimal system prompt: "Be helpful, direct, and technically precise. Focus on accuracy and clarity."
- No personality rules or tone guidelines
- No output style changes
- SDD orchestrator still included (if SDD component installed)

</Tab>

<Tab title="Custom">
### Custom Persona

Bring your own persona instructions. Gentle AI does not modify your agent's system prompt.

**Use case**:
- You have an existing custom persona
- You want to write your own personality
- You're using a team-specific persona

**What happens**:
- Persona component does **nothing**
- Your existing system prompt is untouched
- SDD orchestrator still injected (if SDD component installed)
- Other components (Engram, Context7, etc.) still configure normally

**Recommended structure** for custom personas:

```markdown
---
name: My Custom Persona
description: Brief description
applyTo: "**"
---

## Rules

- [Your rules]

## Personality

[Your personality description]

## Tone

[Your tone guidelines]

## Behavior

- [Your behavior patterns]
```

## OpenCode Tab-switchable agents

OpenCode with Gentleman persona gets two agents:

<CardGroup cols={2}>
<Card title="gentleman" icon="user-tie">
**Mode**: Primary (default)

**Description**: Senior Architect mentor - helpful first, challenging when it matters

**Tools**: write, edit (read-only mode)

**Use for**: Learning, planning, architecture discussions
</Card>

<Card title="sdd-orchestrator" icon="diagram-project">
**Mode**: All (available via Tab)

**Description**: Gentleman personality + SDD delegate-only orchestrator

**Tools**: read, write, edit, bash (full access)

**Use for**: SDD workflows, code implementation, execution
</Card>
</CardGroup>

### Switching agents in OpenCode

```bash
# Press Tab during a conversation to switch agents
# gentleman → sdd-orchestrator → gentleman

# Or start a conversation with specific agent:
opencode --agent sdd-orchestrator
```

## Persona + SDD combination

Gentleman persona includes the SDD orchestrator in the same system prompt. This combination:
- Maintains personality across planning and execution
- Enforces delegation rules (orchestrator never writes code inline)
- Keeps teaching-oriented tone during SDD workflows

**Neutral persona** also gets SDD orchestrator appended (if SDD component is installed), but without personality:
- Professional tone during planning
- Same delegation rules
- No push-back or teaching moments

**Custom persona** users need to manually include SDD orchestrator if they want it.
