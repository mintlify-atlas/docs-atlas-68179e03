## Test Categories

### Unit Tests

Every package has focused unit tests:

```bash
# Run all unit tests
go test ./...

# With coverage
go test -cover ./...

# Verbose output
go test -v ./...
```

**Coverage areas**:

- **System detection**: OS, distro, package manager detection
- **Dependency resolution**: Version parsing, comparison, detection
- **Agent adapters**: Path resolution, capability checks
- **Planner**: Topological sort, dependency expansion
- **Pipeline**: Stage execution, rollback logic
- **File merge**: Section injection, marker parsing
- **Components**: Install logic, config generation

### Integration Tests

Tests that verify component interactions:

```go
func TestInstallPipeline_FullFlow(t *testing.T) {
    // 1. Detect system
    detection := system.Detect(context.Background())
    
    // 2. Resolve dependencies
    plan := planner.Resolve(selection)
    
    // 3. Build stage plan
    stages := cli.BuildStagePlan(plan)
    
    // 4. Execute
    result := orchestrator.Execute(stages)
    
    // 5. Verify
    assert.True(t, result.Success)
}
```

Integration tests cover:
- TUI state transitions
- CLI flag parsing → execution
- Backup → restore → verify flow
- Component injection → verification

### Example: Dependency Resolution Tests

```go
func TestTopologicalSort(t *testing.T) {
    graph := map[ComponentID][]ComponentID{
        "sdd":    {"skills"},
        "skills": {},
        "engram": {},
    }
    
    order, err := TopologicalSort(graph)
    require.NoError(t, err)
    
    // "skills" must come before "sdd"
    skillsIdx := indexOf(order, "skills")
    sddIdx := indexOf(order, "sdd")
    assert.Less(t, skillsIdx, sddIdx)
}
```

## Golden File Testing

Component output is tested against golden files:

```go
func TestPersonaInjection_GentlemanMode(t *testing.T) {
    result := persona.GenerateSystemPrompt("gentleman", "claude-code")
    
    goldenFile := "testdata/persona-gentleman-claude.md"
    if *update {
        os.WriteFile(goldenFile, []byte(result), 0644)
    }
    
    expected, _ := os.ReadFile(goldenFile)
    assert.Equal(t, string(expected), result)
}
```

**Golden files** (`testdata/`):

- Persona templates (gentleman, neutral)
- System prompt sections
- MCP config JSON
- Settings file snippets

To update golden files:

```bash
go test ./... -update
```

## E2E Test Details

### Test Script Structure

E2E tests are bash functions in `e2e/e2e_test.sh`:

```bash
test_install_minimal() {
    echo "TEST: Minimal install (engram only)"
    
    # Run install
    gentle-ai install \
        --agent claude-code \
        --component engram \
        --persona neutral \
        --non-interactive
    
    # Verify config files
    assert_file_exists "$HOME/.claude/CLAUDE.md"
    assert_file_contains "$HOME/.claude/.claude.json" "engram"
    
    # Verify binary
    assert_command_exists "engram"
    
    # Health check
    engram --version
}
```

## CI/CD Testing

Tests run on every commit:

1. **Unit tests**: All packages
2. **Integration tests**: Full pipeline
3. **E2E tests**: Ubuntu + Arch in Docker
4. **Cross-platform builds**: macOS, Linux, Windows

All tests must pass before merge.

## Adding New Tests

### For a New Component

1. Create `internal/components/<name>/<name>_test.go`
2. Test install logic:
   ```go
   func TestInstall_ComponentName(t *testing.T) {
       // Test component installation
   }
   ```
3. Test config generation (use golden files)
4. Test platform-specific paths

### For a New Agent

1. Create `internal/agents/<name>/adapter_test.go`
2. Test all interface methods
3. Test path resolution on all platforms:
   ```go
   func TestAdapter_Paths_CrossPlatform(t *testing.T) {
       // Use filepath.Join, test on Windows too
   }
   ```
4. Test detection logic

### For E2E Scenarios

1. Add function to `e2e/e2e_test.sh`:
   ```bash
   test_my_scenario() {
       echo "TEST: My scenario"
       gentle-ai install --agent ... --component ...
       assert_file_exists "..."
       assert_command_exists "..."
   }
   ```
2. Add to test list in `e2e/docker-test.sh`

## Test Data

Test fixtures in `testdata/`:

- **Golden files**: Expected output for components
- **Mock configs**: Sample agent configurations
- **OS release files**: Sample `/etc/os-release` content
- **Dependency output**: Sample version command output

Never commit sensitive data (API keys, tokens) to test fixtures.
